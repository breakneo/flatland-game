# 国内小游戏合规与防封红线规则 (minigame-compliance-rules)

在设计或编写面向国内小游戏（微信、抖音、快手、支付宝、快游戏）的功能时，必须 100% 遵守以下铁律：

## 1. 社交与分享红线（微信防封核心）
- **禁止诱导分享**：严禁出现“分享到群才可复活”、“分享给好友领取钻石”等强制分享绑定逻辑；
- **禁止检测分享结果**：微信平台已彻底关闭 `onShareAppMessage` 的成功回调参数，任何依赖分享成功的逻辑均属违规或无效；
- **自愿广告替代**：所有获得额外收益的途径必须改为“主动点击激励视频广告（Rewarded Video Ad）”。

## 2. 内容安全与 UGC 减法红线
- **首发版本禁止开放 UGC 文本输入**：严禁在首个版本中开发自定义聊天室、玩家留言板或自定义玩家昵称；
- **强制使用系统随机名**：玩家昵称默认采用随机词库组合（如“机智的方块_883”），免去接入平台敏感词过滤 API（`msgSecCheck`）带来的提审驳回风险。

## 3. 性能与平台崩溃红线
- **iOS 800MB 闪退物理警戒线**：iOS 微信小游戏分配给 WebGL 上下文的内存上限为 800MB~1GB，超过即闪退。切场景必须主动调用资源卸载；
- **4MB 首包红线**：主包代码与资源体积严格 <= 3.5MB，其余资源走远程 CDN；
- **域名白名单**：所有请求必须使用 HTTPS/WSS，且必须在微信后台提前配置。

## 4. 商业化体验保护
- **插屏广告冷却**：插屏广告触发间隔必须 >= 60 秒，单局游戏进行中禁止突然弹出插屏；
- **严禁遮挡误触**：广告关闭按钮必须清晰易触，严禁与核心操作按钮重叠。
